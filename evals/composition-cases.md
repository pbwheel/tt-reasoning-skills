# Composition Cases

## Canonical compositions

| Situation | Expected chain | Why the order matters |
|---|---|---|
| Vague legacy-system complaint | `socratic-clarify -> first-principles` | Define the actual outcome before challenging the inherited design |
| Broad market choice | `deep-research -> steelman-decision` | Build the evidence model before weighing options |
| Research contains disputed critical claims | `deep-research -> fact-audit -> steelman-decision` | Audit only claims capable of changing the choice |
| Innovation blocked by convention and narrow imagination | `first-principles -> cross-domain` | Abstract from essentials before transferring mechanisms |
| Innovation has real functional conflicts | `first-principles -> cross-domain -> expert-panel` | Generate options before multidisciplinary synthesis |
| Benchmark adaptation | `reverse-engineer -> first-principles` | Extract principles, then re-derive for target constraints |
| Benchmark adaptation with uncertain demand | `reverse-engineer -> minimum-experiment` | Test the transferred principle rather than perfecting it in theory |
| Consequential A/B decision | `fact-audit -> steelman-decision` | Establish premises before value-weighted choice |
| Empirically uncertain A/B decision | `steelman-decision -> minimum-experiment` | Find the flip variable, then test it |
| Personal direction | `talent-discovery -> life-design -> minimum-experiment` | Evidence about strengths informs paths; lived tests update them |

## Conditional compositions

| Proposed chain | Accept only when |
|---|---|
| `explain-two-levels -> deep-research` | The explanation explicitly reveals a broad evidence question the user needs answered |
| `socratic-clarify -> deep-research` | Clarification produces a broad, externally answerable research question |
| `deep-research -> fact-audit` | A bounded disputed claim is decision-critical; do not re-audit the entire survey |
| `expert-panel -> steelman-decision` | Model synthesis leaves a value-weighted choice among plausible options |
| `life-design -> steelman-decision` | Future paths are mature enough to compare and the user wants a current commitment |
| `cross-domain -> expert-panel` | Translated mechanisms create genuine disciplinary trade-offs |
| `first-principles -> minimum-experiment` | A derived design rests on an empirically testable critical assumption |

## Invalid by default

| Chain | Failure |
|---|---|
| `expert-panel -> expert-panel` | Recursive role-play adds no new model |
| `steelman-decision -> first-principles` | Chooses before repairing an assumption-bound option set |
| `minimum-experiment -> deep-research` | Returns to analysis after a decisive cheap test exists |
| `deep-research -> explain-two-levels` | Usually means research scope was excessive for an explanation request |
| `talent-discovery -> talent-discovery` | Repeats the same interview instead of updating the evidence model |
| `fact-audit -> deep-research -> fact-audit` | Expands and loops without a new blocking gap |
| Any five-skill chain | Violates minimum sufficiency unless policy is explicitly revised |

## Dynamic stop assertions

A composed workflow passes only if it reassesses after every step:

- If a fact audit decisively eliminates an option, do not steelman a decision that no longer exists.
- If first-principles analysis reveals only one feasible design, do not add a decorative panel.
- If life-design work reveals a safe obvious probe, proceed to experiment design without ranking paths prematurely.
- If clarification reveals the request is a simple factual question, answer it directly or use the appropriate single skill.
